# クラウド学習保存の保護

- 版候補：`2026.1027.0015`。公開前。既存main `4fa7cda0` から `codex/cloud-save-protection-20261026` へ今回の保存保護だけを反映。
- 空の既存端末保存でもクラウドの実履歴を復元。新規開始・全消去・大幅減少を検出した自動上書きを停止し、クラウドの復元を断った場合も自動アップロードしない。初回読込が未完了なら保存しない。
- commit成否が不明なエラーでは、新しい保存片を削除しない。旧世代・孤立片の整理は現行manifestと退避2枠をトランザクションで照合。Firestoreルールも参照中の片削除を拒否する。
- 退避は通常1日1回と、確認済みの手動上書き直前の固定2枠。新しい定期通信は追加せず、通常の保存トランザクション内で退避する。端末への復元時も現在の有意な保存を先に退避し、失敗なら置換しない。本人のUndo・アカウントの境界・既存の保存revisionを維持。
- 原因と再現条件は区別する。本番での特定の削除主体・全履歴の完全復元・全ての故障を防げる保証を主張しない。運営による個別復旧の識別子・原文・保全ファイルは公開差分へ含めない。
- 旧管理用の一括整理も、現在のmanifestや退避を保護せず全保存片を消せる経路があるため、`--execute` を認証・通信より前で停止。診断用dry-runは維持する。
- 開発元では関連PC63件、追加PC7件、単体95件（既存の画像件数試験1件を除外）、Functions41件、ルール48項目、スマホChromium／WebKitの関連24件が通過。開発元の `test:e2e:safe` は画像363件期待／実4,577件の既存固定値で止まるため、全成功とは扱わない。
- 公開用環境の `test:e2e:safe` は単体97件・Functions41件が成功、ブラウザー305/308件成功。初回案内のローカルサーバー接続拒否と復習案内の寸法変動は、各1件を単独で再実行して成功。残りの大規模性能基準は、同じ既存fixture・通信遮断・8,000語超を旧mainと比較し、キューが旧版147.7／151.5ms・今回150.2／153.9ms、表示が旧版149.5／148.0ms・今回150.4／145.3msで両方未達。閾値・性能処理は変更せず、改善や厳密な不変は主張しない。
- 最終の保存保護単体13件（管理スクリプト停止2件を含む）、手動復元の追加PC1件、公開用スマホChromium／WebKitの保存保護・復元・Undo・共通モーダル16件、ルール48項目が成功。版番号だけを最終時刻へ更新し、HTML・版番号同期も確認。全E2E成功とは扱わない。
- FirestoreルールとGitHub Pagesの公開は未実施。Functionsの本体・依存・課金設定・App Check設定は変更しない。個別復旧の原文と保全は公開差分へ含めない。
