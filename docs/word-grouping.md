# 単語カード統合（2026-09-09）

## 実装範囲

- 主CEFR層の同じ綴りを1枚にする。対象891語・元の1,909行を統合し、主CEFR全体は8,018行から7,000カードになる。綴りの大文字小文字や別表記は勝手に同一視しない。
- 所属は原則A1→A2→B1→B2の初級側。点検済みの例外は元先頭行の`studyLevel`で指定し、学習キーは維持する。元の用法別レベル・意味・フレーズ・例文・発音は `senses` に保持する。原データの修復は個別記録を残す。[第1回の所属・入口修復](a1-level-repair-01-2026-09-09.md)。
- 単語帳の参照行も統合カードと同じ学習キー・用法を使う。参照ではない単語帳独自の収録語を綴りだけで巻き込まない。
- 発音が異なる場合は品詞付きで併記。意味カードには全用法とフレーズ、既存例文欄には高さ44pxの用法選択欄（品詞＋フレーズ）。読み上げは選択中の例文を使う。
- 品詞分類の修復時は `legacyKeyPos` で既存キーを維持する。表示・品詞フィルターには修正後の `pos` を使用し、統合版番号は変更しない。[第3回修復・最新表示確認](phrase-pos-repairs-batch-03-2026-09-09.md)。
- 品詞フィルターは含まれる品詞のどれかに一致すれば出題し、カード内は全用法を表示する。単語一覧も全用法で検索できる。正誤操作と判定・配点式は従来どおりで、1回答を品詞数分に増やさない。
- 名詞イラストは用法別の元レベルで照合し、統合で消えないようにする。

## 旧履歴の削除（承認済み）

- 統合対象の旧 `wordStates`・`srsData`・`learnedWordIntervals`（`_last` も含む）を削除して未学習にする。保存用コピー／バックアップは作らない。保存後、この旧履歴は回答Undoでは戻せない。
- 対象外の学習履歴・累積ポイント・復習スコア・獲得済みスコアの送信待ちイベントは保持する。
- 初回移行は古い綴りキー・品詞別キー・単語帳参照の別名キーを対象にする。`wordGroupingVersion: 1` を保存し、移行後の統合キーの新しい履歴は維持する。古いクラウド保存の復元も通常の再読込で同じ移行を通る。
- 統合キーには初級側先頭行の既存v2キーを使うため、サーバー許可リスト内に収まる。旧キーは送信待ちスコアのため許可リストに残す。サーバー配点・保存リビジョンによる競合保護は変更しない。
- 公開手順・検証記録は [運用記録](operations.md) を参照。公開時は通常のバージョン更新を行い、複数端末も更新する。今後統合対象を増やす際は、新たな対象だけの移行を設計し、版番号を機械的に上げて既存統合語を再リセットしない。

- 通常Webフォント版は `before-fonts/` と `after-fonts/`。変更前は原データを従来の個別カード描画で再表示し、変更後は本体の統合処理の出力を使用する。元の実装前撮影は `before/` に残す。
- 幅1280px／390px、Chromium。実アプリのカードから例文欄までの画像。クラウド等の外部書込みを遮断し、回答履歴を付けずに表示する。インストール案内は検証用端末設定で非表示。実ユーザーの保存はテストに使わない。
- 物理スマートフォンの確認ではない。全件の文字領域をカード境界と照合し、代表語を目視確認する。文字内側の数pxの句読点のぶら下がりと、カード外へのはみ出しは区別する。
- 全件画像はローカル保存（Git対象外）。生成方法：PowerShellで `$env:WORD_GROUPING_CAPTURE='before'` または `'after'` を指定し `node node_modules/playwright/cli.js test tests/word-grouping-visual.spec.js`。終了後は `Remove-Item Env:WORD_GROUPING_CAPTURE`。一覧は `node scripts/build-word-grouping-review.js` で再生成する。環境変数なしの通常テストは代表8語のみで、全件ログを上書きしない。
